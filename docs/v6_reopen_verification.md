## 法律承诺确实走条约，不是普通外交行动

1. 调用国家面板实际入口`InformationPanelBar.OpenTreatyDraftPanelForNewDraft(PLAYER.Self, SPA.Self)`。
2. 在草稿中加入大清→西班牙的`law_commitment`，输入`law_mercantilism`；读取到法律名“重商主义”、输入完整、条款可用。
3. 无资金条款时西班牙接受度为-47；加入`money_transfer`后，1K/周为-31、2K为-14、3.2K为+6（仍非确定接受），5K为+37且`WillAIAccept=1`。只试改草稿，未逐次签约。
4. 在执行前确认扣除5K/周后仍满足现金/非负预算护栏，再提出5年（1825天）条约。**5K是每周持续转账，不是一次赠礼。** 草稿只含重商主义承诺与资金转让，没有借款、割地、投资权或义务条款。
5. 推进到1846.1.17，生效条约列表出现大清—西班牙“吉安协议”；直接读取条约中的法律、资金、双方国家，确认实际条款相符。
6. 法律观测返回重商主义`valid=True`，面板单检查点成功10%、推进14.3%、受阻5.6%；现有策略的推进/受阻模型评估约95.1%，候选列表也已包含该法。随后通过`Actions.enact_law`实际开始制定，`runner.enacting()`读回`law_mercantilism`，至2月初仍在推进。

这证明“法律为0%时一直等待”并非唯一选择；视频中的条约动作可以打开当前政府下的重商主义。**尚未验证这条法律最终通过，也未验证1836开局签约价格、战争路线或1843前承认。**

## 后续接入自动策略时需要保留的细节

- 无界面上下文时不能用空的`GetPlayer`代替真实玩家国家，使用桥接已有`PLAYER`路径。
- `TreatyDraftPanel`是上下文类型，不能直接当全局单例。实测从`InformationPanelBar.AccessSelf`读取面板数组，通过RTTI确认`CTreatyDraftPanel`，再在真实面板上取得`TreatyDraft`并调用UI方法。仅用于定位的内存读取，没有写游戏内存或改存档数值。正式实现应检查RTTI和双方国家，不能硬编码本次进程地址或面板下标。
- 法律输入走`ArticleDraft.SetLaw`；资金类型key为`money_transfer`，金额走`SetQuantity`。使用`GetArticleType`及条款输入/可用性检查，不能把“命令未报错”当条款已加入。
- 签约必须核验生效条约、输入法律、转账方向/金额，再重读立法可用性；不能只统计发送成功。
- 建造恢复还需接入自动调度：按可负担活动队列估算净周成本，保留现金、非负预算和借款守卫。当前自动runner仍有整批恢复门槛；`resume_construction_cost`只在内存中，载入后默认0也不能视作建造免费。
